Fix a fresh clone failing its very first command

Found by cloning the published repo and running `probe-effort`:

    bridge: unhandled Error: CONFIG_ERROR: Codex CLI not found or not executable.

codex.exe was right there. The cause: `resolveCodexExe` probes candidates with
`cwd: cfg.__workdir`, and `codex.workdir` defaults to `.codex-scratch` -- which is
gitignored, so a fresh clone does not have it. Spawning with a missing cwd fails with
ENOENT and `status: null`, which the resolver read as "this executable does not work".

Proven directly:

    cwd 不存在 -> status: null | error: ENOENT
    cwd 存在   -> status: 0    | version: codex-cli 0.159.2

So a correct executable was reported as missing, with a fix hint ("set codex.exePath")
that would not have helped. Every new user would have hit this on their first command.

The probe now creates the workdir (falling back to the project root if it cannot) and
the resolution succeeds. Verified by deleting .codex-scratch from the export and running
`doctor` and `probe-effort` -- both work.
