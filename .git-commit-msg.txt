Add probe-effort and archive-state; make card limits configurable

Three gaps reported by a real deployment: a research project that ran this
framework across 17 phases and had to work around each one by hand.

1. The card limits were not configurable
   summary hard-coded the list cardinalities (10/5/5) and a 300-char per-entry cap,
   so a project that raised oneLineMaxChars to fit a full report still could not
   lengthen findings -- the content had nowhere to go and got crammed into one
   field. Now: entryMaxChars, maxChangedEntries, maxFindingsEntries,
   maxBlockersEntries, nextHintMaxChars. Long entries are TRUNCATED, not rejected;
   entry counts stay hard failures because they change what the brain must judge.

2. A run's state had no supported way to be retired
   Task ids restart at T-001, so a previous run's cards/T-001.accepted.json lands
   exactly where the next run writes, and its rolling summary can adopt the old
   verdict as its own history. `run init` now warns on stderr about artifacts from
   another run, and `archive-state [--label <why>]` moves state to
   work/run-archives/ with a README recording the run id, span, status, verdict
   breakdown and why it was archived. Nothing is deleted, and it refuses to
   archive a state holding no cards, calls, rounds or run -- a re-archive used to
   report success while archiving nothing.

3. Reasoning tiers were undiscoverable
   codex exec has no flag listing valid tiers, the set is model-specific, and a
   wrong value only failed on a real task. `probe-effort` runs one small problem
   per tier and reports acceptance plus actual reasoning. First real run here:
   minimal rejected; low=133 medium=741 high=1466 xhigh=1502 -- so xhigh exists
   and is the highest tier this model engages, which was not guessable from the
   docs. The probe prompt must require real reasoning: a trivial one measured 0 at
   every tier and made the first version of the advice report "low" as strongest.

Also fixed, all found by running the above:
- parseArgs held a whitelist of value-taking flags, so every new flag silently
  became a boolean (--label before-v2 set label=true and made before-v2 positional)
- help printed its whole block twice, and an unknown verb exited 0
- KNOWN_BOOLEAN_FLAGS was declared after the parseArgs call that reads it
- card validation read cfg.summary without a default, so a config predating the new
  keys would have crashed instead of falling back
